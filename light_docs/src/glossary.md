# 用語集

- **ECS(Entity Component System)**
  - Bevyのアーキテクチャの一部で、エンティティ(Entity)、コンポーネント(Component)、システム(System)の3つの要素から構成される。ECSは、ゲームオブジェクトの状態や挙動を効率的に管理するための設計パターンです。
- **Entity**
  - BevyのECS(Entity Component System)における、ゲーム内のオブジェクトを表す概念。エンティティは、コンポーネントを組み合わせることで、さまざまな特性や挙動を持つことができます。
- **Component**
  - BevyのECS(Entity Component System)における、エンティティに付与されるデータのこと。コンポーネントは、エンティティの状態や属性を表すために使用されます。
- **System**
  - BevyのECS(Entity Component System)における、エンティティとコンポーネントに対して処理を行う関数やロジックのこと。システムは、ゲームの挙動やロジックを実装するために使用されます。
- **Resource**
  - システム間で共有されるデータのこと。リソースは、ゲーム全体で1つだけ存在するグローバルなデータとして扱われます。`Resource`トレイトを実装することで、BevyのECSにおいてリソースとして扱うことができます。`Res`または`ResMut`を使ってシステム内でリソースにアクセスできます。
- **Message**
  - システム間で情報を伝達するための手段。メッセージは、イベントや通知などの形でシステム間でやり取りされます。`Message`トレイトを実装することで、BevyのECSにおいてメッセージとして扱うことができます。`MessageReader`を使ってシステム内でメッセージを受信できます。`MessageWriter`を使ってシステム内でメッセージを送信できます。
- **Observer**
  - エンティティで発生した特定のイベント（トリガー）に反応して実行される処理。`.observe()`でエンティティに登録し、`On<T>`でトリガーの情報を受け取ります。毎フレーム実行される通常のシステムとは異なり、登録したエンティティでイベントが発生したときだけ実行されます。
- **State**
  - ゲームの状態を管理するための仕組み。ステートは、ゲームの進行状況やモードを表すために使用されます。`State`トレイトを実装することで、BevyのECSにおいてステートとして扱うことができます。`Res<State<S>>`からシステム内で現在のStateを取得することができます。`NextState`を使ってシステム内でステートを変更できます。
- **Plugin**
  - システムやリソースをまとめて管理するためのモジュール。プラグインは、ゲームの機能や拡張を追加するために使用されます。`Plugin`トレイトを実装することで、BevyのECSにおいてプラグインとして扱うことができます。`App`にプラグインを追加することで、システムやリソースをまとめて管理できます。
- **Commands**
  - ゲームの世界(World)に対する変更を予約しておくための仕組み。`Commands`は、エンティティの生成や削除、コンポーネントの追加や削除など、ゲームの状態を変更する操作をまとめて行うことができます。システム内で`Commands`を使って、ゲームの状態を変更する操作を予約し、次のフレームで実行されます。
- **SystemSet**
  - システムをグループ化して管理するための仕組み。`SystemSet`は、関連するシステムをまとめて管理し、実行順序や条件を指定することができます。`SystemSet`を使って、システムの実行順序や条件を制御することができます。
- **module**
  - Rustのモジュールシステムにおける、コードの名前空間を表す概念。モジュールは、関連する関数や構造体、列挙型などをまとめるために使用されます。`mod`キーワードを使ってモジュールを定義し、`use`キーワードを使って他のモジュールからアクセスできます。
- **crate**
  - Rustのコンパイル単位を表す概念。クレートは、Rustのコードをまとめるための単位であり、ライブラリやバイナリなどの形態で提供されます。`Cargo.toml`ファイルでクレートの依存関係を管理し、`use`キーワードを使って他のクレートからアクセスできます。
- **所有権**
  - Rustのメモリ管理の仕組みで、変数やデータの所有権を明示的に管理することを指す。所有権は、データのライフタイムや借用のルールを定めることで、安全なメモリ管理を実現します。Rustでは、変数がスコープを抜けると自動的にメモリが解放されるため、メモリリークやダングリングポインタなどの問題を防ぐことができます。
- **借用**
  - Rustの所有権システムにおける、データへの参照を一時的に借りることを指す。借用は、データの所有権を移動させずに、他の変数や関数からデータにアクセスするための手段です。Rustでは、借用には不変借用と可変借用の2種類があり、それぞれのルールに従ってデータへのアクセスが制御されます。
    - **不変借用**
      - データへの読み取り専用の参照を指す。不変借用は、データの内容を変更せずに読み取るための手段です。いくらでも不変借用は同時に複数存在できます。`&`を使って不変借用を作成します。
    - **可変借用**
      - データへの読み書き可能な参照を指す。可変借用は、データの内容を変更するための手段です。ただ１つの可変借用しか存在できません。`&mut`を使って可変借用を作成します。
- **ライフタイム**
  - Rustの所有権システムにおける、変数やデータの有効期間を表す概念。ライフタイムは、データの参照が有効である期間を明示的に指定することで、安全なメモリ管理を実現します。Rustでは、ライフタイムを明示的に指定することで、コンパイル時に参照の有効性をチェックし、メモリ安全性を保証します。
- **トレイト**
  - Rustの型システムにおける、共通の振る舞いを定義するための抽象的な概念。トレイトは、構造体や列挙型などの型に対して、特定のメソッドや関連関数を実装するための契約を提供します。Rustでは、トレイトを使ってポリモーフィズムを実現し、異なる型に共通のインターフェースを提供することができます。
