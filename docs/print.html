はじめに

この資料について

この資料はGammaのBevy初心者向けBevy入門ガイドです。
「Bevyなんか一回も触ったことない」という初心者でも安心してBevyを始められるよう、基本的なところからUnityの使い方を解説し、簡単なゲームを作れるところまでリードしていきます。(Bevy公式ドキュメントhttps://bevy.org/)(Rust公式日本語ドキュメントhttps://doc.rust-jp.rs/book-ja/)


↑こんな感じの帰宅ゲームを作っていきます！

まずは自分のパソコンの中にBevyの作品を入れるフォルダを作成し、そこに光の資料のGoogleドライブにあるzipファイル(Googleドライブのリンク)を展開します。
エクスプローラーを開き、PC＞ローカルディスク（C:）の中に「BevyWorks」フォルダを作成しましょう。（慣れている方はお好みでどうぞ。）
光の資料のドライブにある「bevy_sample_game.zip」を右クリック、「すべて展開」を選択し、参照ボタンから先ほど作成した「BevyWorks」フォルダを選択して.zipファイルを展開します。

環境構築

続いてゲーム作成に必要なRustの開発環境一式とプログラムを書くのに必要なテキストエディタであるVSCodeをダウンロード、インストールしていきます。
概要のみ記載しているので、Rustの公式ドキュメントを参考にしたり、VSCodeは既に入れている人に教えてもらいながら進めましょう。

rustupをインストールする

まずは、Rustの日本語公式ドキュメント(the book)に従って、Rustのバージョンと関連するツールを管理する「rustup」をインストールします。
軽く公式ドキュメントに書いてあることをまとめると、以下の手順でインストールできます。

  1. https://rust-lang.org/tools/install/に行き、DOWNLOAD RUSTUP-INIT.EXE(X64)をクリックしてダウンロードします。
  2. ダウンロードした「rustup-init.exe」を実行します。
  3. インストールの途中で、Visual StudioのC++ビルドツールをインストールするか聞かれるので、まだインストールしていない場合はインストールしてください。
  • 「C++によるデスクトップ開発」(“Desktop Development with C++”)
  • Windows 10または11のSDK
  • 英語の言語パック(English language pack)コンポーネント
  1. インストールできたかを確認する
  • rustc --versionとcargo --versionをターミナルで実行し、バージョンが表示されればOKです。一応簡単にそれぞれ説明すると、rustcはRustのコンパイラ、cargoはRustのビルドツール兼パッケージマネージャーです。

VSCodeをインストールする

BevyではRustという言語でプログラムを書いていくことになります。
このガイドではVSCodeと呼ばれるテキストエディタ(テキストファイルを編集するソフト)を用いることとします。(任意のエディタを使っても構いません。なんならメモ帳でも(おすすめはしない))
公式サイト（https://code.visualstudio.com/download）にアクセスしてダウンロード、インストーラを起動して指示に従ってインストールします。基本的にデフォルトの設定で問題ないと思いますが、「PATHへの追加」の項目はONにしておきましょう。
VSCodeを起動し、拡張機能の検索欄に「rustanalyzer」と入力し、RustAnalyzerをインストールします。

次のページからゲーム制作が始まります。
途中で様々なエラーが表示されるかと思いますが、この資料のおまけページにガイドで出そうなエラー集のページを設けているので、そちらを参考にしてみたり、rustのコンパイラはエラーメッセージが非常に親切なので、ちゃんと読んでみると解決できることが多いです。また、rustc --explain <エラー番号>でエラーの詳細を確認できます。

ゲームを作ってみよう!

まずは、はじめにでダウンロードしたサンプルゲームのディレクトリをテキストエディタで開いたり、ターミナルでビルド&実行してみましょう。
CLI(Command Line Interface)での操作に慣れていない人もいるかと思いますが、使えると便利ですし、この資料では簡単なコマンドしか使わないので、ぜひ覚えていきましょう。

# ディレクトリを開く
# ここでは、Cドライブの直下にBevyWorksというフォルダを作成し、その中にゲームのサンプルを展開したと仮定しています。
# ゲームのzipファイルを展開した場所は人によって違うと思うので、適宜読み替えてください。
cd BevyWorks/bevy_sample_game
# VSCodeで開く
code .
# ビルド&実行する
cargo run

一応説明しておくと、cargo runは、Rustのビルドツール兼パッケージマネージャーであるCargoに「ビルドして実行してね」とお願いするコマンドです。 ビルドだけする場合はcargo buildを使います。 リリースビルドをする場合はcargo build --releaseのように--releaseとつけます。

矢印キーor WASDキーでキャラクターを動かすことができます。

試しに、プレイヤーの移動スピードや敵の移動スピードを変えてみましょう。

src/player/mod.rsの中にある

#![allow(unused)]
fn main() {
impl Default for Player {
    fn default() -> Self {
        // デフォルトの移動速度を設定
        Self { speed: 200.0 }
    }
}
}

という箇所のspeedの値を変えると、プレイヤーの移動スピードが変わります。

似たような感じでenemyの移動スピードも変えられます。

src/enemy.rsの中にenemyのspeedの値を変える箇所があるので、探して変えてみましょう。

値を変えたら、再度cargo runでビルド&実行して、ゲーム内での挙動を確認してみましょう。

プロジェクトの作成

先ほどのサンプルゲームのようなものを実際に0から作っていきます！
まずは、プロジェクトを作成するために、ターミナルでBevyWorksディレクトリ(ディレクトリ名は人それぞれなので読み替えてください)にいる状態で以下のコマンドを実行します。

cargo new game

これを実行すると、BevyWorksディレクトリの中にgameという名前のディレクトリが作成され、その中にRustのプロジェクトの雛形が作成されます。

次に、作成したプロジェクトをVSCodeで開きます。

code ./game

開くと以下のようなディレクトリ構造になっていると思います。

game
├── Cargo.lock
├── Cargo.toml
├── target/
└── src/
    └── main.rs

それぞれのフォルダの解説を軽くすると、Cargo.lockは依存関係のバージョンを固定するためのファイル(人間が直接いじることはほとんどない)、Cargo.tomlはプロジェクトの設定や依存関係を記述するファイル、target/はビルドした際に生成されるファイルが入るディレクトリ、src/はソースコードを置くディレクトリで、その中のmain.rsがエントリーポイントとなるRustのソースコードです。

このままでもRustのプロジェクトとしてはビルド&実行できますが、Bevyを使うためにCargo.tomlに依存関係を追加していきます。
Cargo.tomlを開き、以下のように書き換えます。

[package]
name = "game"
version = "0.1.0"
edition = "2024"

[profile.dev]
opt-level = 1
[profile.dev.package."*"]
opt-level = 3
[features]
dynamic_linking = ["bevy/dynamic_linking"]

[dependencies]
bevy = "0.20.1"
bevy_rapier2d = "0.37.0"
serde = { version = "1.0", features = ["derive"] }
toml = "1.1"
anyhow = "1.0"

Bevyを使えるようにするために、[dependencies]のところにbevy = "0.20.1"を追加しました。
また、bevy_rapier2dは物理演算を行うためのライブラリで、serdeはデータのシリアライズ/デシリアライズを行うためのライブラリ、tomlはTOML形式のデータを扱うためのライブラリ、anyhowはエラー処理を簡単にするためのライブラリです。

クレート(crate)は、Rustコンパイラが一度に考慮する最小限のコードです。クレートは2種類の形態のうちいずれかです:バイナリクレートか、ライブラリクレートです。バイナリクレート(binary crate)は、 コマンドラインプログラムやサーバなどの実行可能形式にコンパイルされ、実行することができるプログラムです。ライブラリクレート(library crate)は、main関数を持たず、実行可能形式へとコンパイルされません。代わりに、複数のプロジェクトで共有されることを想定した機能を定義するものです。「クレート」と言うときの、ほとんどの場合それはライブラリクレートのことであり、一般的なプログラミング概念の「ライブラリ」と同じ意味で使用します。

この辺はとりあえずそうしておけばいいと思ってれば[profile.dev]のopt-levelはビルドの最適化レベルを指定するもので、自分で書いたコードは頻繁に変更されるため、最適化レベルを下げて開発効率を上げます。
[profile.dev.package.“*”]のopt-levelは、すべての依存関係に対して最適化レベルを3に設定するためのものです。
[features]のdynamic_linkingはBevyの動的リンクを有効にするための設定です。

次に、.cargo/config.tomlを作成し、以下のように書きます。より高速にビルドするための設定です。

[target.x86_64-pc-windows-msvc]
linker = "rust-lld.exe"

これで、プロジェクトの作成とBevyの依存関係の追加が完了しました。
次のステップでは、実際にゲームを作るためのコードを書いていきます。

ゲーム画面を表示する

現在の状態でcargo runでビルド&実行しても標準出力(ターミナル)にHello, world!と表示されるだけで、ゲーム画面は表示されません。
ゲーム画面を表示するためには、BevyのAppにDefaultPluginsを追加する必要があります。
src/main.rsを開き、以下のように書き換えます。src/main.rsはプログラムのエントリーポイントであるmain関数が書かれるファイルです

#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")] // リリースビルドではコンソールを非表示にする
use bevy::prelude::*; // Bevyの基本機能一式(Unityでのusing UnityEngine;に相当する)

// エントリーポイント
fn main() {
    App::new() // Bevyアプリケーションを作成
        .add_plugins(DefaultPlugins) // デフォルトプラグインを追加。これでウィンドウが表示されるようになる
        .run(); // アプリの起動
}


これでゲームのウィンドウが立ち上がるようになりました。
このページのこれから先は、ウィンドウの大きさやフルスクリーンにするかなどの設定ファイルを作成して、それを読み込むことで、ゲームのウィンドウの設定を変更していきます。少しめんどくさいので、最初はこのままでも構いません。

ウィンドウのサイズ等についての設定ファイルを作成する

まず、プロジェクトディレクトリ直下にsettings/settings.tomlというファイルを作成します。ここにウィンドウのサイズやタイトル、フルスクリーンモード、VSyncの有効/無効などの設定を記述します。
中は以下のような形式で書きます

[window]
width = 800
height = 600
title = "Game"
fullscreen = false
vsync = true

設定ファイルをビルド時に実行ファイルと同じディレクトリにコピーする

次に、build.rsというファイルをプロジェクトディレクトリ直下に作成し、以下のように書きます。build.rsは、Cargoがビルドする際に自動的に実行されるスクリプトです。ここでは、settings/settings.tomlをビルド時に実行ファイルと同じディレクトリにコピーする処理を行います。

use std::fs;
use std::path::Path;

fn main() {
    // 実行ファイルの出力先ディレクトリを取得
    let out_dir = std::env::var("OUT_DIR").unwrap();

    // target/debug or target/releaseに辿る
    let target_dir = Path::new(&out_dir).ancestors().nth(3).unwrap();

    // コピー先のパス
    let dest = target_dir.join("settings/");
    // コピー元のパス
    let src = Path::new("settings/");

    // 既存削除
    if dest.exists() {
        fs::remove_dir_all(&dest).unwrap();
    }

    // コピー
    copy_dir_all(src, &dest).unwrap();
}

// 再帰コピー
fn copy_dir_all(src: impl AsRef<Path>, dst: impl AsRef<Path>) -> std::io::Result<()> {
    fs::create_dir_all(&dst)?;

    for entry in fs::read_dir(src)? {
        let entry = entry?;
        let ty = entry.file_type()?;

        if ty.is_dir() {
            copy_dir_all(entry.path(), dst.as_ref().join(entry.file_name()))?;
        } else {
            fs::copy(entry.path(), dst.as_ref().join(entry.file_name()))?;
        }
    }

    Ok(())
}

設定ファイルを読み込む

src/settings.rsというファイルを作って以下のように書きます。ここでは、設定の構造体の定義と、設定ファイルを読み込む関数を定義しています。

#![allow(unused)]
fn main() {
use bevy::prelude::*;
use serde::{Deserialize, Serialize};

// 設定を表す構造体
#[derive(Resource, Debug, Clone, Deserialize, Serialize)]
pub struct Settings {
    pub window: WindowSettings,
}

// ウィンドウ設定を表す構造体
#[derive(Debug, Clone, Deserialize, Serialize)]
pub struct WindowSettings {
    pub width: u32,
    pub height: u32,
    pub title: String,
    pub fullscreen: bool,
    pub vsync: bool,
}

// デフォルトの設定を提供するための実装
impl Default for Settings {
    fn default() -> Self {
        Self {
            window: WindowSettings {
                width: 800,
                height: 600,
                title: "Game".to_string(),
                fullscreen: false,
                vsync: true,
            },
        }
    }
}

use std::fs;

use anyhow::Error;

// 設定をロードする関数
fn load_settings() -> Result<Settings, Error> {
    let settings_str = fs::read_to_string("settings/settings.toml")?;
    let settings: Settings = toml::from_str(&settings_str)?;
    Ok(settings)
}

// 設定を取得する関数。ロードに失敗した場合はデフォルト設定を返す。
pub fn get_settings() -> Settings {
    match load_settings() {
        Ok(settings) => settings,
        Err(err) => {
            error!(target: "game", "Failed to load settings: {err}");
            Settings::default()
        }
    }
}
}

また、src/main.rsを以下のように書き換えます。

#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")] // リリースビルドではコンソールを非表示にする

use bevy::{prelude::*, window::WindowResolution};
mod settings; // 設定のモジュールをインポート


fn main() {
    // settings/settings.tomlから設定を読み込む
    let settings = settings::get_settings();
    // Bevyアプリケーションを作成
    let mut app = App::new();
    // デフォルトプラグインを追加し、ウィンドウ設定を上書きする
    app.add_plugins(DefaultPlugins.set(WindowPlugin {
        primary_window: Some(Window {
            title: settings.window.title.clone(),
            resolution: WindowResolution::new(settings.window.width, settings.window.height),
            mode: if settings.window.fullscreen {
                bevy::window::WindowMode::BorderlessFullscreen(MonitorSelection::Primary)
            } else {
                bevy::window::WindowMode::Windowed
            },
            present_mode: if settings.window.vsync {
                bevy::window::PresentMode::AutoVsync
            } else {
                bevy::window::PresentMode::AutoNoVsync
            },
            ..default()
        }),
        ..default()
    }));
    // 設定をリソースとしてアプリに挿入
    app.insert_resource(settings);
    // アプリの起動
    app.run();
}

これでsettings/settings.tomlの内容に応じて、ゲームのウィンドウのサイズやタイトル、フルスクリーンモード、VSyncの有効/無効を設定できるようになりました。
適当に数値を変えて、cargo runでビルド&実行してみましょう。

ゲーム全体の状態をStateで管理する

今回作るゲームでは大きく分けて、ゲームプレイ中, 終了(クリア or ゲームオーバー)の2つの状態が存在します。src/state.rsというファイルを作って以下のようにゲームの状態の定義をします。BevyのStateを使うことで、ゲームの状態を簡単に管理することができます。

#![allow(unused)]
fn main() {
use bevy::prelude::*;

// ゲームの状態を定義
#[derive(Debug, Default, Clone, Eq, PartialEq, Hash, Copy, States)]
pub enum GameState {
    #[default]
    Playing,
    Ending,
}
}

}

プレイヤーの移動と表示

まず、Updateの実行順序を制御するために、src/game_play_set.rsというファイルを作成し、以下のコードを追加します。システムセットを使うことで、プレイヤーの入力、検出、移動、描画の順番を制御することができます。

#![allow(unused)]
fn main() {
use bevy::prelude::*;

// 実行順を制御するためのシステムセットを定義
#[derive(SystemSet, Debug, Hash, PartialEq, Eq, Clone, Copy)]
pub enum GamePlaySet {
    Input,
    Detection,
    Movement,
    Rendering,
}

pub struct GamePlaySetPlugin;

impl Plugin for GamePlaySetPlugin {
    fn build(&self, app: &mut App) {
        app.configure_sets(
            Update,
            (
                GamePlaySet::Input,
                GamePlaySet::Detection.after(GamePlaySet::Input),
                GamePlaySet::Movement.after(GamePlaySet::Detection),
                GamePlaySet::Rendering.after(GamePlaySet::Movement),
            )
                .chain(),
        );
    }
}
}

そしたら、src/player/mod.rsというファイルを作成し、PlayerについてのものをまとめるプラグインとPlayerコンポーネントとPlayerをスポーンするための関数を作成します。mod.rsはmain.rs同様に名前が固定のファイルで、そのディレクトリのモジュールを定義するファイルです。
Playerコンポーネントは、プレイヤーの移動スピードを保持するためのコンポーネントです。

#![allow(unused)]
fn main() {
use bevy::prelude::*;
use bevy_rapier2d::prelude::*;

pub struct PlayerPlugin;

impl Plugin for PlayerPlugin {
    fn build(&self, app: &mut App) {
        
    }
}

// プレイヤーのコンポーネント
// 移動速度を保持する
#[derive(Component)]
pub struct Player {
    speed: f32,
}

// デフォルトトレイトを実装
impl Default for Player {
    fn default() -> Self {
        // デフォルトの移動速度を設定
        Self { speed: 200.0 }
    }
}

impl Player {
    // プレイヤーをスポーンしてエンティティを返す関数
    // エンティティはidとして返され、後で参照するために使用できる
    pub fn spawn(commands: &mut Commands, position: Vec3, texture: Handle<Image>) -> Entity {
        commands
            .spawn((
                // 速度を持つプレイヤーコンポーネントを追加
                Player::default(),
                // Transformコンポーネントを追加して位置を設定
                Transform::from_translation(position),
                // 長方形のコライダーを追加
                Collider::cuboid(25.0, 25.0),
                // 2D物理エンジンの剛体を追加
                RigidBody::Dynamic,
                // 重力の影響を受けないように設定
                GravityScale(0.0),
                // 回転をロックして、プレイヤーが回転しないように設定
                LockedAxes::ROTATION_LOCKED,
                // 衝突時のイベントを有効化
                ActiveEvents::COLLISION_EVENTS,
                // 速度を初期化
                Velocity::default(),
                // Continuous Collision Detectionを有効化
                Ccd::enabled(),
                // スプライトを追加して見た目を設定
                Sprite {
                    image: texture.clone(),
                    custom_size: Some(Vec2::new(50.0, 50.0)),
                    ..default()
                },
            ))
            .id()
    }
}
}

次にプレイヤーの入力を処理するシステムを作成します。src/player/input.rsというファイルを作成し、以下のコードを追加します。ここにはキー入力をVec2で表すリソースと、入力に応じてその値を更新するシステムを作成します。また、キーの組み合わせを表す構造体も作成します。
MoveDirectionというリソースを作成し、矢印キーやWASDキーの入力に応じて、x軸とy軸の方向をVec2で表します。リソースはBevyの仕組みで、システム間で共有されるデータを保持するためのものです。世界に1つだけ存在するグローバルなデータとして扱われます。
set_move_directionシステムは、入力に応じてMoveDirectionを更新するシステムです。add_systemsでUpdateで登録しているので、毎フレーム呼ばれます。引数にRes<ButtonInput<KeyCode>>を受け取ることで、現在押されているキーの情報を取得できます。システムからリソースにアクセスするには、ResやResMutを使います。Resは読み取り専用、ResMutは書き込み可能なリソースを取得するためのものです。ここではButtonInput<KeyCode>とKeyConfigを読み取り専用で取得し、MoveDirectionを更新するために書き込み可能で取得しています。
KeyBinding構造体は、複数のキーの組み合わせを表すための構造体です。最大4つのキーを保持できるようにしています。pressedメソッドは、今のフレームで押されているかどうかを判定するためのメソッドです。
KeyConfig構造体は、プレイヤーの移動に使用するキー設定を保持するためのリソースです。デフォルトでは、WASDキーと矢印キーの組み合わせを設定しています。

#![allow(unused)]
fn main() {
use crate::game_play_set::GamePlaySet;
use bevy::prelude::*;

pub struct PlayerInputPlugin;

impl Plugin for PlayerInputPlugin {
    fn build(&self, app: &mut App) {
        app.insert_resource(MoveDirection::default())
            .insert_resource(KeyConfig::default())
            .add_systems(Update, set_move_direction.in_set(GamePlaySet::Input));
    }
}

// 入力情報を2次元ベクトルで表すリソース
#[derive(Resource, Debug, Clone, Copy, Default)]
pub struct MoveDirection(pub Vec2);

// 入力に応じてMoveDirectionを更新するシステム
pub fn set_move_direction(
    keyboard_input: Res<ButtonInput<KeyCode>>,
    key_config: Res<KeyConfig>,
    mut move_direction: ResMut<MoveDirection>,
) {
    let mut direction = Vec2::ZERO;
    if key_config.up.pressed(&keyboard_input) {
        direction.y += 1.0;
    }
    if key_config.down.pressed(&keyboard_input) {
        direction.y -= 1.0;
    }
    if key_config.left.pressed(&keyboard_input) {
        direction.x -= 1.0;
    }
    if key_config.right.pressed(&keyboard_input) {
        direction.x += 1.0;
    }
    move_direction.0 = direction.normalize_or_zero();
}

// キーの組み合わせを表す構造体
// 複数キーの組み合わせをサポートするため、最大4つのキーを保持できるようにする
#[derive(Clone, Copy, Debug)]
pub struct KeyBinding {
    keys: [Option<KeyCode>; KeyBinding::MAX_KEYS],
}

impl KeyBinding {
    // 最大キー数を定義する定数
    pub const MAX_KEYS: usize = 4;
    // 新しいKeyBindingを作成するコンストラクタ
    pub const fn new(keys: [Option<KeyCode>; KeyBinding::MAX_KEYS]) -> Self {
        Self { keys }
    }
    // 今のフレームで押されているかどうかを判定する
    pub fn pressed(&self, input: &ButtonInput<KeyCode>) -> bool {
        self.keys.iter().flatten().any(|&key| input.pressed(key))
    }
}

// プレイヤーの移動に使用するキー設定を保持するリソース
#[derive(Resource, Debug, Clone, Copy)]
pub struct KeyConfig {
    pub up: KeyBinding,
    pub down: KeyBinding,
    pub left: KeyBinding,
    pub right: KeyBinding,
}

// デフォルトのキーコンフィグ
impl Default for KeyConfig {
    fn default() -> Self {
        Self {
            up: KeyBinding::new([Some(KeyCode::KeyW), Some(KeyCode::ArrowUp), None, None]),
            down: KeyBinding::new([Some(KeyCode::KeyS), Some(KeyCode::ArrowDown), None, None]),
            left: KeyBinding::new([Some(KeyCode::KeyA), Some(KeyCode::ArrowLeft), None, None]),
            right: KeyBinding::new([Some(KeyCode::KeyD), Some(KeyCode::ArrowRight), None, None]),
        }
    }
}
}

#![allow(unused)]
fn main() {
use super::*;
use crate::goal::Goal;
use bevy::ecs::query::{QueryData, QueryFilter};
use bevy_rapier2d::prelude::CollisionEvent;

pub struct PlayerCollisionPlugin;

impl Plugin for PlayerCollisionPlugin {
    fn build(&self, app: &mut App) {
        app.add_systems(
            Update,
            check_collisions.in_set(crate::game_play_set::GamePlaySet::Detection),
        );
    }
}

// ２つのエンティティのうち、指定されたクエリに一致する最初のエンティティを返す関数
fn find_entity<Q: QueryData, F: QueryFilter>(
    first: Entity,
    second: Entity,
    query: &Query<Q, F>,
) -> Option<Entity> {
    [first, second]
        .into_iter()
        .find(|entity| query.get(*entity).is_ok())
}

// プレイヤーとゴール、敵との衝突を検出するシステム
fn check_collisions(
    players: Query<Entity, With<Player>>,
    goals: Query<Entity, With<Goal>>,
    mut collision_events: MessageReader<CollisionEvent>,
) {
    for event in collision_events.read() {
        // 衝突イベントが開始された場合のみ処理する
        let CollisionEvent::Started(first, second, _) = event else {
            continue;
        };

        // 衝突したエンティティのうち、プレイヤーに該当するエンティティを取得する
        let Some(player_entity) = find_entity(*first, *second, &players) else {
            continue;
        };

        // 衝突したエンティティのうち、ゴールまたは敵に該当するエンティティを取得する
        if let Some(goal_entity) = find_entity(*first, *second, &goals) {
            debug!(
                target: "game",
                "Player {:?} collided with Goal {:?}",
                player_entity, goal_entity
            );
        }
    }
}
}

まず、src/ending/mod.rsというファイルを作成し、ゲーム終了時に送信するメッセージの定義と、そのメッセージを処理するシステムを作ります。EndingMessageという列挙型を作り、ゲームクリアとゲームオーバーの2種類のメッセージを定義します。
EndingStateというリソースを作り、ゲーム終了時の状態を保持します。EndingMessageには、リザルト画面での背景色とテキストを返すメソッドを実装します。
handle_ending_messageシステムは、ゲーム終了時に送信されるメッセージを処理し、ゲーム状態をEndingに変更するシステムです。

#![allow(unused)]
fn main() {
use bevy::prelude::*;
use crate::state::GameState;
pub struct EndingPlugin;

// ゲーム終了メッセージを定義する列挙型
#[derive(Message, Copy, Clone, Debug)]
pub enum EndingMessage {
    Clear,
    GameOver,
}

// ゲーム終了状態を保持するリソース
#[derive(Resource, Debug, Clone, Default)]
pub struct EndingState {
    pub message: Option<EndingMessage>,
}

impl EndingMessage {
    // リザルト画面での背景色を返すメソッド
    pub fn background_color(&self) -> Color {
        match self {
            EndingMessage::Clear => Color::srgb(0.0, 1.0, 0.0),
            EndingMessage::GameOver => Color::srgb(1.0, 0.0, 0.0),
        }
    }
    // リザルト画面でのテキストを返すメソッド
    pub fn text(&self) -> &'static str {
        match self {
            EndingMessage::Clear => "Game Clear !!!!!!!!!!!!!!!!!!!!!!!!",
            EndingMessage::GameOver => "Game Over !!!!!!!!!!!!!!!!!!!!!!!!",
        }
    }
}

impl Plugin for EndingPlugin {
    fn build(&self, app: &mut App) {
        app.add_message::<EndingMessage>()
            .insert_resource(EndingState::default())
            .add_systems(
                Update,
                handle_ending_message.in_set(crate::game_play_set::GamePlaySet::Detection),
            );
    }
}

// ゲーム終了メッセージを処理するシステム
fn handle_ending_message(
    mut ending_message: MessageReader<EndingMessage>,
    mut state: ResMut<NextState<GameState>>,
    mut ending_state: ResMut<EndingState>,
) {
    for message in ending_message.read() {
        debug!(target: "game", "Ending message received: {:?}", message);
        // ゲーム終了状態を更新し、ゲーム状態をEndingに設定する
        ending_state.message = Some(*message);
        // GameStateをEndingに変更する
        state.set(GameState::Ending);
    }
}

}

UIを作成します。src/ending/ui.rsというファイルを作成し、ゲーム終了時のUIを表示するシステムを追加します。restart_buttonオブザーバーでリスタートボタンが有効化されると、ゲーム状態をPlayingに戻してゲームをリスタートします。

オブザーバーは、特定のエンティティで発生したイベントをきっかけに呼び出される処理です。通常のシステムが毎フレーム実行されるのに対して、オブザーバーは監視対象のエンティティで指定したトリガーが発生したときだけ実行されます。ここではActivateがボタンのクリックに相当し、On<Activate>でそのイベントを受け取ります。.observe(restart_button)をボタンに付けることで、そのボタンが有効化されたときにrestart_buttonが呼び出されます。

#![allow(unused)]
fn main() {
use crate::{ending::EndingMessage, state::GameState};
use bevy::prelude::*;
use bevy::picking::hover::Hovered;
use bevy::ui::Pressed;
use bevy::ui_widgets::{Activate, Button};

// リスタートボタンのコンポーネント
#[derive(Component)]
pub struct RestartButton;

// ゲーム終了時のUIを表示するプラグイン
pub struct EndingUiPlugin;

impl Plugin for EndingUiPlugin {
    fn build(&self, app: &mut App) {
        app.add_systems(
            Update,
            update_restart_button.in_set(crate::game_play_set::GamePlaySet::Input),
        )
        .add_systems(OnEnter(GameState::Ending), spawn_ending_ui);
    }
}

fn update_restart_button(
    mut button_query: Query<(&Hovered, Has<Pressed>, &mut BackgroundColor), With<RestartButton>>,
) {
    for (hovered, pressed, mut color) in &mut button_query {
        color.0 = if pressed {
            Color::srgb(0.35, 0.75, 0.35)
        } else if hovered.get() {
            Color::srgb(0.25, 0.25, 0.25)
        } else {
            Color::srgb(0.15, 0.15, 0.15)
        };
    }
}

fn restart_button(
    _activate: On<Activate>,
    mut state: ResMut<NextState<GameState>>,
    mut ending_state: ResMut<super::EndingState>,
) {
    debug!(target: "game", "Restart button clicked!");
    state.set(GameState::Playing);
    ending_state.message = None;
}

// ゲーム終了時のUIを生成するシステム
pub fn spawn_ending_ui(
    mut commands: Commands,
    jp_font: Res<crate::fonts::JpFont>,
    ending_state: Res<super::EndingState>,
) {
    let ending = match ending_state.message {
        Some(message) => message,
        None => {
            debug!(target: "game", "No ending message found, defaulting to GameOver");
            EndingMessage::GameOver
        }
    };
    let canvas = commands
        .spawn((
            Node {
                width: percent(100.0),
                height: percent(100.0),
                align_items: AlignItems::Center,
                justify_content: JustifyContent::Center,
                flex_direction: FlexDirection::Column,
                ..default()
            },
            BackgroundColor(ending.background_color()),
            DespawnOnExit(GameState::Ending),
        ))
        .id();
    let text = commands
        .spawn((
            Node {
                max_width: percent(100.0),
                ..default()
            },
            Text::new(ending.text()),
            TextFont {
                font: jp_font.0.clone().into(),
                font_size: FontSize::Px(50.0),
                ..default()
            },
            TextLayout::justify(Justify::Center),
            TextColor(Color::WHITE),
        ))
        .id();
    let restart_button = commands
        .spawn((
            Button,
            Hovered::default(),
            RestartButton,
            Node {
                width: px(200.0),
                height: px(50.0),
                align_items: AlignItems::Center,
                justify_content: JustifyContent::Center,
                ..default()
            },
            BackgroundColor(Color::default()),
            children![
                Node {
                    max_width: percent(100.0),
                    ..default()
                },
                Text::new("Restart"),
                TextFont {
                    font: jp_font.0.clone().into(),
                    font_size: FontSize::Px(30.0),
                    ..default()
                },
                TextLayout::justify(Justify::Center),
                TextColor(Color::WHITE),
            ],
        ))
        .observe(restart_button)
        .id();
    // canvasの子としてtextとrestart_buttonを追加
    commands
        .entity(canvas)
        .add_children(&[text, restart_button]);

#![allow(unused)]
fn main() {
// プレイヤーとゴール、敵との衝突を検出するシステム
fn check_collisions(
    players: Query<Entity, With<Player>>,
    goals: Query<Entity, With<Goal>>,
    mut collision_events: MessageReader<CollisionEvent>,
    mut ending_message: MessageWriter<EndingMessage>, // ゲーム終了メッセージを送信するためのMessageWriter
) {
    for event in collision_events.read() {
        // 衝突イベントが開始された場合のみ処理する
        let CollisionEvent::Started(first, second, _) = event else {
            continue;
        };

        // 衝突したエンティティのうち、プレイヤーに該当するエンティティを取得する
        let Some(player_entity) = find_entity(*first, *second, &players) else {
            continue;
        };

        // 衝突したエンティティのうち、ゴールまたは敵に該当するエンティティを取得する
        if let Some(goal_entity) = find_entity(*first, *second, &goals) {
            debug!(
                target: "game",
                "Player {:?} collided with Goal {:?}",
                player_entity, goal_entity
            );
            // ゲームクリアのメッセージを送信する
            ending_message.write(EndingMessage::Clear);
        }
    }
}
}

用語集

  • ECS(Entity Component System)
    • Bevyのアーキテクチャの一部で、エンティティ(Entity)、コンポーネント(Component)、システム(System)の3つの要素から構成される。ECSは、ゲームオブジェクトの状態や挙動を効率的に管理するための設計パターンです。
  • Entity
    • BevyのECS(Entity Component System)における、ゲーム内のオブジェクトを表す概念。エンティティは、コンポーネントを組み合わせることで、さまざまな特性や挙動を持つことができます。
  • Component
    • BevyのECS(Entity Component System)における、エンティティに付与されるデータのこと。コンポーネントは、エンティティの状態や属性を表すために使用されます。
  • System
    • BevyのECS(Entity Component System)における、エンティティとコンポーネントに対して処理を行う関数やロジックのこと。システムは、ゲームの挙動やロジックを実装するために使用されます。
  • Resource
    • システム間で共有されるデータのこと。リソースは、ゲーム全体で1つだけ存在するグローバルなデータとして扱われます。Resourceトレイトを実装することで、BevyのECSにおいてリソースとして扱うことができます。ResまたはResMutを使ってシステム内でリソースにアクセスできます。
  • Message
    • システム間で情報を伝達するための手段。メッセージは、イベントや通知などの形でシステム間でやり取りされます。Messageトレイトを実装することで、BevyのECSにおいてメッセージとして扱うことができます。MessageReaderを使ってシステム内でメッセージを受信できます。MessageWriterを使ってシステム内でメッセージを送信できます。
  • Observer
    • エンティティで発生した特定のイベント（トリガー）に反応して実行される処理。.observe()でエンティティに登録し、On<T>でトリガーの情報を受け取ります。毎フレーム実行される通常のシステムとは異なり、登録したエンティティでイベントが発生したときだけ実行されます。
  • State
    • ゲームの状態を管理するための仕組み。ステートは、ゲームの進行状況やモードを表すために使用されます。Stateトレイトを実装することで、BevyのECSにおいてステートとして扱うことができます。Res<State<S>>からシステム内から現在のStateを取得することができます。NextStateを使ってシステム内でステートを変更できます。
  • Plugin
    • システムやリソースをまとめて管理するためのモジュール。プラグインは、ゲームの機能や拡張を追加するために使用されます。Pluginトレイトを実装することで、BevyのECSにおいてプラグインとして扱うことができます。Appにプラグインを追加することで、システムやリソースをまとめて管理できます。
  • Commands
    • ゲームの世界(World)に対する変更を予約しておくための仕組み。Commandsは、エンティティの生成や削除、コンポーネントの追加や削除など、ゲームの状態を変更する操作をまとめて行うことができます。システム内でCommandsを使って、ゲームの状態を変更する操作を予約し、次のフレームで実行されます。
  • SystemSet
    • システムをグループ化して管理するための仕組み。SystemSetは、関連するシステムをまとめて管理し、実行順序や条件を指定することができます。SystemSetを使って、システムの実行順序や条件を制御することができます。
  • module
    • Rustのモジュールシステムにおける、コードの名前空間を表す概念。モジュールは、関連する関数や構造体、列挙型などをまとめるために使用されます。modキーワードを使ってモジュールを定義し、useキーワードを使って他のモジュールからアクセスできます。
  • crate
    • Rustのコンパイル単位を表す概念。クレートは、Rustのコードをまとめるための単位であり、ライブラリやバイナリなどの形態で提供されます。Cargo.tomlファイルでクレートの依存関係を管理し、useキーワードを使って他のクレートからアクセスできます。
  • 所有権
    • Rustのメモリ管理の仕組みで、変数やデータの所有権を明示的に管理することを指す。所有権は、データのライフタイムや借用のルールを定めることで、安全なメモリ管理を実現します。Rustでは、変数がスコープを抜けると自動的にメモリが解放されるため、メモリリークやダングリングポインタなどの問題を防ぐことができます。
  • 借用
    • Rustの所有権システムにおける、データへの参照を一時的に借りることを指す。借用は、データの所有権を移動させずに、他の変数や関数からデータにアクセスするための手段です。Rustでは、借用には不変借用と可変借用の2種類があり、それぞれのルールに従ってデータへのアクセスが制御されます。
      • 不変借用
        • データへの読み取り専用の参照を指す。不変借用は、データの内容を変更せずに読み取るための手段です。いくらでも不変借用は同時に複数存在できます。&を使って不変借用を作成します。
      • 可変借用
        • データへの読み書き可能な参照を指す。可変借用は、データの内容を変更するための手段です。ただ１つの可変借用しか存在できません。&mutを使って可変借用を作成します。
  • ライフタイム
    • Rustの所有権システムにおける、変数やデータの有効期間を表す概念。ライフタイムは、データの参照が有効である期間を明示的に指定することで、安全なメモリ管理を実現します。Rustでは、ライフタイムを明示的に指定することで、コンパイル時に参照の有効性をチェックし、メモリ安全性を保証します。
  • トレイト
    • Rustの型システムにおける、共通の振る舞いを定義するための抽象的な概念。トレイトは、構造体や列挙型などの型に対して、特定のメソッドや関連関数を実装するための契約を提供します。Rustでは、トレイトを使ってポリモーフィズムを実現し、異なる型に共通のインターフェースを提供することができます。
